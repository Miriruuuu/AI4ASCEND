**结论：反映完全成立。而且根因不是搜索、不是评估 —— 是 AI 在浏览器里**根本没拿到植物信息**。**

## 一、事实：AI 攻击 5 次，4 次被化解

用**真实引擎**重放回放（血量逐步校验 0/43 处不符），并对 AI 每一次攻击
**枚举全部防守应对**（~70 种/次）：

| AI 攻击（手） | 攻击值 | 能反打它的防守 | 实际结果 |
|---|---|---|---|
| 第 15 手 c32 | 3 | 2 / 69（c30 伤2、c31 伤1） | ❌ 被反打 2（6→4） |
| 第 17 手 c68 | 3 | 0 / 75 | ✅ 有效，打掉玩家 3 点（6→3） |
| 第 23 手 c34 | 4 | 2 / 73（c36 伤1、c40 伤2） | ❌ 被反打 2（4→2） |
| 第 35 手 c56 | 4 | 0 / 70（另有 2 种抵消） | ❌ 被抵消（0 伤） |
| 第 41 手 c37 | 4 | 2 / 72（c41 伤2、c77 伤1） | ❌ **被反打 2 → 阵亡**（2→0） |

关键：能反打它的那 2 个格，在它攻击**之前**就已经是"玩家一步成线"的格 —— 完全可见。
所以这不是"看不见的危险"，而是 AI 的**伤害算术算错了**。

## 二、定位过程

1. **固定深度扫描**：`decideMove` 在第 41 手用 depth 1~8 **全部**首选 `c41`（封堵玩家成线），
   而实机下了 `c37`（攻击）→ **实机跑的不是"直算"这条路径**。
2. **参数变体排查**：把植物上下文摘掉后，第 41 手正好选 `c37`（攻击）。
3. **忠实复刻浏览器路径**（client 打包消息 → worker 解析）：`normal` 难度下
   **4/4 步完全复现实机落点**（第 15/23/35/41 手）。

## 三、根因

```ts
// client.ts（发出）—— 发的是一整个对象，字段名 magic
...(request.magic === undefined ? {} : { magic: request.magic }),

// worker.ts（接收）—— 读的是扁平的 magicPlants / magicDamagePerPlant
...(request.magicPlants && request.magicPlants.length > 0 ? { magic: { plants: request.magicPlants } } : {}),
```

`magicPlants` / `magicDamagePerPlant` **全项目没有任何地方写过**（`grep` 只有 worker 在读）。
⇒ **实机（浏览器里走 Worker）的 AI 永远没有植物上下文。**

三条症状同一个根因：

1. **反击强度按"没有植物"算**：第 41 手玩家防守的连珠是 `4 子 + 2 棵植物 = 6`，
   AI 以为是 `4`，正好等于自己的攻击值 → 以为只会"**抵消**"（0 伤），实际**被反打 2 点致命**。
   这就是"反复送死"的机制。
2. **看不见植物资源** → 整局只认领 1 棵（还是成线顺带），玩家认领 7 棵。
3. **技能要花植物** → AI 以为自己一棵都没有 → **整局 0 次技能**。

> 为什么之前所有测试都没抓到：node / jsdom **没有 `Worker`**，
> `AiClient` 会**静默退回同步 `decideMove`**（那条路径一直是对的）；
> 所有基准脚本也都绕开 client 直接调 `decideMove`。
> 也就是 **"脚本里的 AI" ≠ "实机里的 AI"**。

## 四、修复

- 新增 `src/ai/protocol.ts`：协议收敛为 **`{ id, request: AiRequest }` 整体透传**
  （`buildWorkerMessage` / `readWorkerRequest` 严格互逆），不再逐字段拼装
  ⇒ 字段名漂移在结构上不可能发生。
- `client.ts` / `worker.ts` 改用上述函数；`AiMoveRequest` 直接就是 `AiRequest`（删掉重复声明）。
- 新增 `tests/ai-worker.spec.ts`：① 植物/技能经 `structuredClone` 原样送达；
  ② **行为锁**：合成局面里"知道反击 = 4 子 + 2 棵植物 = 6"时 AI 会封堵对手的反击线，
  "看不到植物"时它会去成线送死。
- 新增 `scripts/diagnose-replay.ts`：回放诊断工具
  （真实引擎重放校验 + 每次攻击枚举全部防守 + `--decisions` 用当前 AI 重算对比）。

## 五、验证

- `pnpm typecheck` ✅；单测 **87 项全绿**（新增 2）。
- 修复后 worker 路径与直算**逐点一致**：第 41 手由 `c37`（送死）→ `c41`（封堵）。
- 平衡数据**不受影响**（循环赛/对撞脚本不走 worker），此前结论仍然有效。
